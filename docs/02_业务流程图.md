# 访客登记系统业务流程图

> 来源:[01_PRD.md](01_PRD.md) §4 整体业务流程、§5 页面功能需求。图中引用编号对应 PRD 章节。

## 1. 主业务流程图(访客侧)

```mermaid
flowchart TD
    START([访客扫码进入 H5页面]) --> CHK1{localStorage 存在<br>visitor_id?}
    CHK1 -- 否 --> NEW[判定:新用户<br>自动生成 visitor_id 并存储]
    CHK1 -- 是 --> QRY[提交 visitor_id 至后台查询]
    QRY --> CHK2{后台查询到<br>用户信息?}
    CHK2 -- 未查到 --> NEW
    CHK2 -- 查到 --> OLD[判定:老用户<br>反馈用户信息至前端]

    NEW --> INFO[《用户信息》页<br>姓名 / 手机号 / 单位 / 头像]
    INFO --> INFO_SUB[校验通过,提交<br>含 visitor_id]
    INFO_SUB --> APPLY[《申请单》页]

    OLD --> CHK3{当前日期存在<br>有效审批记录?}
    CHK3 -- 无 --> APPLY
    CHK3 -- 有 --> CHK4{审批记录状态}
    CHK4 -- 未审批 / 通过 --> LIST[《访客预约列表》页]
    CHK4 -- 拒绝 --> CHK5{当日拒绝数?}
    CHK5 -- 拒绝数小于 3 --> APPLY
    CHK5 -- 拒绝数达 3 次及以上 --> LIST

    APPLY --> APPLY_FORM[填写申请单<br>被访问人 / 开始时间 / 结束时间 / 访问事由]
    APPLY_FORM --> SUBMIT[提交申请]
    SUBMIT --> SUCCESS[《登记成功》页]
    SUCCESS --> CLOSE[点击「关闭」]
    CLOSE --> LIST

    LIST --> PROFILE[点击顶部用户信息区]
    PROFILE --> MYINFO[《我的信息》页<br>修改姓名 / 手机号 / 单位 / 头像]
    MYINFO --> LIST
```

**分支提醒说明**(对应 PRD §5.1.5):

| 场景 | 跳转 | 提醒 |
|---|---|---|
| 拒绝数 < 3 再次进入申请单 | 《申请单》页 | 弹窗提醒「存在审批人拒绝情况,申请次数剩余:**N** 次」(N = 3 - 当日拒绝数) |
| 拒绝数 ≥ 3 | 《访客预约列表》页 | 弹窗提醒「审批人拒绝近期访问,谢谢。」 |
| 拒绝数 ≥ 3 时尝试提交申请 | 入口拦截 | 禁止提交,提示「审批人拒绝近期访问,谢谢。」 |

## 2. 被访人选择流程(申请单页内)

```mermaid
flowchart TD
    A[点击「被访问人」输入框<br>输入框只读,禁止手输] --> B["弹出被访人查询弹窗(模态)"]
    B --> C[输入姓名关键字]
    C --> D[点击「搜索」]
    D --> E{查询结果?}
    E -- 有结果 --> F[结果列表<br>radio 单选 / 部门 / 姓名]
    E -- 无结果 --> G[空态提示]
    G --> C
    F --> H[点击「确认」]
    H --> I[被访人姓名自动填入输入框<br>关闭弹窗]
    I --> J[继续填写其他字段<br>时间 / 事由]
```

## 3. 邮件审批时序图

```mermaid
sequenceDiagram
    autonumber
    participant V as "访客(用户)"
    participant FE as "访客前端"
    participant BE as "后台系统"
    participant EM as "邮箱"
    participant P as "被访问人"

    V->>FE: 填写申请单并提交(§5.3)
    FE->>BE: 提交申请单
    BE-->>FE: 提交成功
    FE->>V: 弹出《登记成功》页

    BE->>BE: 生成审批链接,携带不可预测的 token
    BE->>EM: 发送审批邮件至被访问人邮箱<br>含「审批」/「拒绝」按钮
    EM->>P: 收到审批邮件

    P->>FE: 点击邮件内「审批」/「拒绝」按钮
    FE->>BE: 跳转《审批确认》页,token 鉴权
    BE-->>FE: 返回申请详情<br>申请人 / 单位 / 时间 / 事由

    P->>FE: 点击「批准」/「拒绝」(无二次确认,直接回写)
    FE->>BE: 回写审批结果
    BE->>BE: 状态流转:未审批 → 通过 / 拒绝(条件更新防重复审批)
    BE-->>FE: 审批完成提示

    Note over V,FE: 访客再次进入 H5 时,列表页展示最新审批状态
```

## 6. 门卫核验流程(线下人工,访客到厂区门口时)

```mermaid
flowchart TD
    A[访客到厂区门口] --> B[出示手机《访客预约列表》页]
    B --> C{门卫核对身份信息<br>头像 / 姓名 / 单位 与本人一致?}
    C -- 不一致 --> N1[不放行]
    C -- 一致 --> D{有效审批记录状态}
    D -- 通过 --> E[放行进入厂区]
    D -- 未审批 --> N2[不放行<br>提示等待被访人审批完成]
    D -- 拒绝或无有效记录 --> N3[不放行]
```

**核验判定说明**:

| 核验结果 | 门卫动作 |
|---|---|
| 身份一致,且记录状态为「通过」 | 放行进入厂区 |
| 身份一致,状态为「未审批」 | 不放行,提示访客等待审批完成 |
| 身份一致,状态为「拒绝」或页面无有效记录 | 不放行 |
| 身份与页面不一致(疑似冒用) | 不放行 |
