> 版本：v1.0（2026-08-13）
> 依据：`docs/01_PRD.md`（v1.2）§5 页面功能需求、§6 数据需求；后端框架：若依 RuoYi v3.9.2（Spring Boot 4）
> 配套：`docs/02_业务流程图.md`；本文档为前后端接口与数据库表的**权威契约**，变更需双方同步并记录版本

## 1. 通用约定

### 1.1 响应格式

统一沿用若依 `AjaxResult` 格式：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": { }
}
```

| code | 含义 | 前端处理 |
|---|---|---|
| 200 | 成功 | 正常流程 |
| 400 | 参数校验失败（缺失/格式错误） | 展示 msg 提示 |
| 401 | 审批 token 无效或已过期 | 审批页提示「链接无效或已过期」 |
| 601 | 业务拦截（warn，如当日拒绝数 ≥ 3 禁止申请、申请单已完成审批） | 展示 msg 提示，按 PRD 对应文案 |
| 500 | 系统异常 | 展示「操作失败，请稍后重试」 |

> 说明：601 沿用若依 `AjaxResult.warn(msg)` 惯例；400 用于参数级校验（PRD §7 要求校验失败提示具体原因）。

### 1.2 通用字段格式

- 时间：`yyyy-MM-dd HH:mm:ss`（GMT+8，后端 Jackson 已配置）
- 金额/整数：Java long/int
- 手机号：11 位字符串
- `visitorId`：UUID 格式字符串（36 位含连字符），由**前端生成**并存入 localStorage
- 接口前缀：`/visitor/**`，**全部匿名访问**（不依赖若依登录态）

### 1.3 鉴权说明

- 访客侧接口（user/upload/host/application/list）无登录态，以 `visitorId` 标识用户；后端校验其 UUID 格式（PRD §8 后台校验兜底）
- 审批侧接口（approve）以 URL 参数 `token`（JWT）鉴权，见 §5

## 2. 数据库表结构（MySQL，库 `ry-vue`）

### 2.1 访客表 `visitor`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| visitor_id | varchar(36) | PK | 前端生成 UUID |
| name | varchar(20) | NOT NULL | 姓名 |
| phone | varchar(11) | NOT NULL | 手机号 |
| company | varchar(100) | NOT NULL | 单位 |
| avatar | varchar(255) | NOT NULL | 头像相对路径 `/profile/...`（**必填**，同源解析，见 §3.4） |
| create_time | datetime | NOT NULL | 注册时间 |
| update_time | datetime | 默认 NULL | 更新时间 |

### 2.2 申请单表 `visitor_application`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| application_id | varchar(36) | PK | 申请单号，后端生成 UUID |
| visitor_id | varchar(36) | NOT NULL, KEY | 所属访客 |
| host_id | bigint | NOT NULL | 被访人（sys_user.user_id） |
| host_name | varchar(30) | NOT NULL | 被访人姓名冗余（展示防变更） |
| start_time | datetime | NOT NULL | 开始时间（不早于当前日期） |
| end_time | datetime | NOT NULL | 结束时间（晚于开始时间） |
| reason | varchar(200) | NOT NULL | 访问事由 |
| status | char(1) | NOT NULL DEFAULT '0' | 0 未审批 / 1 通过 / 2 拒绝 |
| approve_time | datetime | 默认 NULL | 审批完成时间 |
| create_time | datetime | NOT NULL | 提交时间 |
| update_time | datetime | 默认 NULL | 更新时间 |

索引：`idx_visitor_id`（visitor_id）、`idx_status`（status）。

### 2.3 被访人（复用若依 `sys_user`，不新建表）

- 被访人 = `sys_user` 中 `status='0'`（正常）且 `del_flag='0'`（未删除）的用户
- 姓名取 `nick_name`，部门取关联 `sys_dept.dept_name`（`sys_dept.status='0'`），邮箱取 `sys_user.email`（用于发审批邮件）
- **后续可选增强**：如需要区分「哪些用户可被访」，在 `sys_user` 增加 `host_enabled char(1)` 字段（'1' 可被访），由后台管理；本次契约按全部正常用户可查设计

### 2.4 建表 DDL

```sql
-- 访客表
create table visitor (
  visitor_id   varchar(36)   not null comment '访客ID(前端生成UUID)',
  name         varchar(20)   not null comment '姓名',
  phone        varchar(11)   not null comment '手机号',
  company      varchar(100)  not null comment '单位',
  avatar       varchar(255)  not null comment '头像相对路径(/profile/...)',
  create_time  datetime      not null comment '注册时间',
  update_time  datetime      default null comment '更新时间',
  primary key (visitor_id)
) engine=innodb comment = '访客信息表';

-- 申请单表
create table visitor_application (
  application_id varchar(36)  not null comment '申请单号(后端生成UUID)',
  visitor_id     varchar(36)  not null comment '访客ID',
  host_id        bigint       not null comment '被访人(sys_user.user_id)',
  host_name      varchar(30)  not null comment '被访人姓名',
  start_time     datetime     not null comment '开始时间',
  end_time       datetime     not null comment '结束时间',
  reason         varchar(200) not null comment '访问事由',
  status         char(1)      not null default '0' comment '状态(0未审批 1通过 2拒绝)',
  approve_time   datetime     default null comment '审批时间',
  create_time    datetime     not null comment '提交时间',
  update_time    datetime     default null comment '更新时间',
  primary key (application_id),
  key idx_visitor_id (visitor_id),
  key idx_status (status)
) engine=innodb comment = '访客申请单表';
```

## 3. 接口契约

### 3.1 用户信息查询（老用户判断）

`GET /visitor/user?visitorId={visitorId}`

- 参数：`visitorId`（必填，UUID）
- 成功响应（查到）：

```json
{ "code": 200, "msg": "操作成功", "data": { "user": {
  "visitorId": "uuid", "name": "张三", "phone": "13800000000",
  "company": "庆铃集团", "avatar": "/profile/upload/2026/08/14/xxx.jpg" } } }
```

- 查无（新用户）：`data.user = null`
- 校验失败（visitorId 非 UUID）：code=400

### 3.2 新用户注册

`POST /visitor/user`

- Body（JSON）：

```json
{ "visitorId": "uuid", "name": "张三", "phone": "13800000000", "company": "庆铃集团", "avatar": "/profile/upload/2026/08/14/xxx.jpg" }
```

- 校验：name 非空 ≤20；phone 符合 `1[3-9]` 开头的 11 位大陆手机号；company 非空；avatar 非空（**必填**）
- 成功：`{ "code": 200, "msg": "注册成功" }`
- 重复注册（visitor_id 已存在）：code=601，msg「该用户已注册」→ 前端按老用户处理
- 校验失败：code=400 + 具体 msg

### 3.3 用户信息更新（我的信息页）

`PUT /visitor/user`

- Body 同 §3.2（visitorId 必填）
- 校验规则同 §3.2
- 成功：`{ "code": 200, "msg": "更新成功" }`；visitorId 不存在：code=601

### 3.4 头像上传（匿名）

`POST /visitor/upload`

- Content-Type：`multipart/form-data`，字段名 `file`（图片，前端先压缩再传）
- 成功：`{ "code": 200, "msg": "上传成功", "data": { "url": "/profile/upload/2026/08/14/xxx.jpg" } }`
- `url` 为**相对路径**（`/profile/...`）：前端按当前页面源解析渲染（`<img src="/profile/...">`），不拼接请求 Host，避免跨环境（dev/prod）图片地址失效；开发环境由 vite 代理 `/profile` 转发，生产由 Web 服务器将 `/profile` 反代至后端（与 `/visitor` 同理，见 §6）
- 失败：code=400（非图片/超限），msg 说明
- 实现：复用若依 `FileUploadUtils`（`ruoyi-common`），匿名 controller 暴露，不走 `/common/upload`（该接口需登录态）

### 3.5 被访人查询

`GET /visitor/host/search?keyword={keyword}`

- 参数：`keyword`（必填，姓名关键字，模糊匹配 `sys_user.nick_name`）
- 成功：

```json
{ "code": 200, "msg": "操作成功", "data": { "list": [
  { "userId": 100, "name": "李四", "deptName": "研发部门", "email": "lisi@qq.com" } ] } }
```

- 空结果：`list = []`（前端展示空态，可重新搜索）
- 仅返回状态正常（status='0'、del_flag='0'）用户；不返回手机号等无关敏感字段

### 3.6 申请单提交

`POST /visitor/application`

- Body（JSON）：

```json
{ "visitorId": "uuid", "hostId": 100, "startTime": "2026-08-14 09:00:00", "endTime": "2026-08-14 11:00:00", "reason": "业务洽谈" }
```

- 后端兜底校验（PRD §5.3、§8）：
  - visitorId 有效（UUID 且已注册）；hostId 存在且为正常用户
  - startTime ≥ 当前时间（当天零点起）；endTime > startTime；reason 非空 ≤200
  - **当日拒绝数 ≥ 3 拦截**：code=601，msg「审批人拒绝近期访问，谢谢。」（PRD §5.1.5 入口拦截，后端兜底）
- 成功流程：生成 `applicationId`（UUID）→ 状态 0 → 发送审批邮件（见 §5.2）→ 返回：

```json
{ "code": 200, "msg": "提交成功", "data": { "applicationId": "uuid" } }
```

### 3.7 审批记录查询

`GET /visitor/application/list?visitorId={visitorId}`

- 返回**有效记录**（当前日期在 start_time ~ end_time 范围内，PRD §5.5 门卫核验窗口期）+ 当日拒绝数：

```json
{ "code": 200, "msg": "操作成功", "data": {
  "todayRejectCount": 1,
  "records": [
    { "applicationId": "uuid", "hostName": "李四", "startTime": "2026-08-14 09:00:00",
      "endTime": "2026-08-14 11:00:00", "reason": "业务洽谈", "status": "0",
      "createTime": "2026-08-13 10:00:00" } ] } }
```

- `todayRejectCount`：该访客**当日**（自然日，GMT+8）被拒绝的审批记录总数（含非有效记录），次日清零（按日统计，非存储字段）
- 记录按 createTime 倒序
- **前端配合（PRD v1.3）**：列表页实时展示**当前时间戳**（日期+时间，前端本地时间，防截图冒用，无需后端时间）；空态仅展示空状态图标**无文案**

### 3.8 审批详情查询（token 鉴权）

`GET /visitor/approve/detail?token={jwt}`

- 成功（状态为未审批，可审批）：

```json
{ "code": 200, "msg": "操作成功", "data": {
  "application": { "applicationId": "uuid", "visitorName": "张三", "visitorCompany": "庆铃集团",
    "hostName": "李四", "startTime": "2026-08-14 09:00:00", "endTime": "2026-08-14 11:00:00",
    "reason": "业务洽谈", "status": "0", "createTime": "2026-08-13 10:00:00" } } }
```

- **已审批（重复点击邮件链接，只能审批一次）**：code=601 业务拦截：

```json
{ "code": 601, "msg": "该申请单已完成审批", "data": { "applicationId": "uuid", "status": "1" } }
```

  前端统一提示 msg，**不渲染申请详情审批操作区**。
- token 无效/过期：code=401，msg「链接无效或已过期」

> 响应语义：200 = 可审批（展示详情+操作区）；601 = 已审批（拦截提示）；401 = token 无效/过期。

### 3.9 审批结果回写

`POST /visitor/approve`

- **前端交互（PRD v1.3）**：审批页点击「批准」/「拒绝」**直接调用本接口**（无二次确认弹窗）
- Body（JSON）：`{ "token": "jwt", "action": "approve" | "reject" }`
- 校验：token 有效（§5.1）；申请单状态须为 0（未审批），**条件更新 `WHERE status='0'` 防重复**——这是「只能审批一次」的**最终兜底**：即使绕过详情页直接调用本接口，已审批申请单影响行数为 0，返回 code=601「该申请单已完成审批」
- 成功：`{ "code": 200, "msg": "审批完成" }`；状态流转 `0 → 1`（approve）/ `0 → 2`（reject），写入 approve_time

## 4. 后端实现要点（RuoYi-Springboot4）

- **模块**：新增业务代码放 `ruoyi-system`（domain/mapper/service）与 `ruoyi-admin`（controller，`com.ruoyi.web.controller.visitor` 包）
- **匿名放行**：`/visitor/**` 在 `SecurityConfig.filterChain` 追加 `.requestMatchers("/visitor/**").permitAll()`，或使用 `@Anonymous` 注解（`com.ruoyi.common.annotation.Anonymous`，PermitAllUrlProperties 自动扫描）
- **代码生成器**（可选）：`ruoyi-generator/src/main/resources/generator.yml` 需调整 `packageName: com.ruoyi.visitor`、`tablePrefix: sys_,visitor_`；生成后按若依惯例装配
- **响应**：controller 继承 `BaseController`，用 `AjaxResult.success()/error()/warn()` 组装
- **时间与拒绝数统计**：拒绝数按 GMT+8 自然日统计（`WHERE visitor_id=? AND status='2' AND approve_time >= 当日零点`）

## 5. 安全与邮件

### 5.1 审批 JWT 设计

- 算法：HS512（jjwt 现有依赖）；**独立密钥**配置项 `approve.secret`（与若依登录 `token.secret` 解耦）。注意 jjwt 0.9.x 将字符串密钥按 **Base64 解码**为字节使用，配置值必须是标准 Base64 字符串（当前明文为 `IsuzuVisitorApproveSecret`）
- Claims：`{ appId: application_id, exp: 签发时间 + 7 天 }`
- 由后端在申请单提交成功后生成，写入审批邮件链接：`{H5域名}/approve?token={jwt}`
- 校验：解析签名 → 校验 exp → 取 appId 查申请单；任何一步失败返回 code=401
- 说明：JWT 自带 exp 与签名，无需 Redis 存储；已审批判断以库中状态为准（防重复点击）

### 5.2 审批邮件

- 依赖：新增 `spring-boot-starter-mail` 到 `ruoyi-admin/pom.xml`（当前未引入）
- 配置（`application.yml`，占位，SMTP 服务器信息由部署方提供——PRD §2.3 邮件服务器配置不在本 PRD 范围）：

```yaml
spring:
  mail:
    host: smtp.xxx.com
    port: 465
    username: xxx
    password: xxx
    properties.mail.smtp.ssl.enable: true
```

- 发送时机：申请单提交成功后，发至被访人邮箱（`sys_user.email`）
- 邮件内容：申请人姓名/单位、访问时间、事由摘要 + 两个按钮链接：
  - 审批：`{H5域名}/approve?token={jwt}`（进入页面后由被访问人选择批准/拒绝）
  - 拒绝：`{H5域名}/approve?token={jwt}`（同一链接，操作在页面内完成）
- 失败处理：邮件发送失败**不影响**申请单提交成功（记录日志，可重发机制后续补充）

## 6. 前后端联调约定

- 前端 API baseURL：`VITE_API_BASE_URL` 环境变量（`.env.development` 等，前端项目当前无 .env 文件，需新建）
- 开发代理：`vite.config.js` 新增 `server.proxy`：`/visitor` → `http://localhost:8080`、`/profile` → `http://localhost:8080`（后端 8080 端口；`/profile` 用于头像等上传文件，同源访问图片）
- 时间参数：前端提交 `yyyy-MM-dd HH:mm:ss`；日期选择控件取值后格式化
- 错误处理：前端统一拦截 code ≠ 200，toast 展示 msg；401 在审批页展示「链接无效或已过期」
